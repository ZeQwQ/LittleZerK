# 对话记录：记忆摘要格式优化

**日期:** 2026-10-06 16:00
**项目:** openharness-agent-loop
**主题:** 优化记忆摘要格式，节约 token 防止上下文紊乱

---

## 问题

用户反馈之前的摘要压缩效果不好：
1. 每 5 条消息就压缩，频繁摘要可能丢失重要上下文
2. 格式冗余（`[关键实体]` `[已完成]` 等），占用 token 多
3. 摘要可能与后续对话产生冲突（上下文紊乱）

---

## 解决方案

### 1. 压缩阈值调整
- 从 5 条改为 10 条，减少频繁压缩

### 2. 新摘要格式 K:|A:|P:

**格式说明：**
```
K:关键信息1|关键信息2|关键信息3...
A:已完成的任务或结论
P:待处理的问题或用户的下一步意图
```

**示例：**
```
K:用户问北京天气|助手查北京晴22C|助手给穿衣建议(薄外套)
A:完成天气查询并回答
P:任务完成
```

### 3. 摘要生成提示词优化

**核心要求：**
- K 行：列出关键实体、已完成查询、获取到的数据等
- A 行：当前任务是否完成
- P 行：用户可能的下一步意图
- 总字数控制在 150 字以内
- 直接输出，不加 `##` 等标记

### 4. 检索输出优化

**旧格式：**
```
[完整历史上下文 - 按时间顺序]

【历史摘要 2026-10-06 14:30】
[关键信息]
北京天气晴...
[/完整历史上下文]
```

**新格式：**
```
[历史
[10-06 14:30]
K:用户问北京天气|助手查北京晴22C|助手给穿衣建议
A:完成天气查询并回答
P:任务完成
]
```
